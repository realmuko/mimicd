# v3 架构：引擎当手，会话当脑子

> 2026-11-17 · 对应 `tools/daemon.ts`、`src/daemon/`、`lib/bridge.js`（旧仓库）
> 一句话：**手机上的事（看、点、打字、发表情）全在引擎里，像不像她的话全在 DSH 会话里，中间只传「待办」和「一句话」。**

---

## 1. 三个部件

```
┌──────────────────────────── 真机（USB） ────────────────────────────┐
│  微信 8.0.80 · 1080×2160                                            │
│       ▲ 触摸注入（android/injector: app_process 起的 dex）            │
│       │   压力 / 接触面积 / 按压时长 / 轨迹都可控                     │
│       │ 截图（screencap）· 输入法广播（ADBKeyboard）                  │
└───────┼─────────────────────────────────────────────────────────────┘
        │ adb（仅本机、仅这一台）
┌───────▼──────────────── 引擎 mimicd（独立 Node 进程）────────────────┐
│  感知   截图 + Windows OCR（scale 4）· 页面判定 · 链接卡片 · 稳定帧     │
│  世界   会话状态 / 多重集去重 / 最近上下文（JSON 落盘，可从事件重建）    │
│  策略   白名单 · 静默时段 · 冷却 · 限频 · 群聊 judge（全在代码里）       │
│  能力   声明式技能（JSON）：send_text / send_sticker_mood /            │
│         collect_sticker / read_summary / read_article / read_screen  │
│  事件   data/events/<day>/run-*.jsonl，每步一行，可回放               │
│  HTTP   127.0.0.1:65480（见 §5）                                      │
└───────┬─────────────────────────────────────────────────────────────┘
        │ HTTP（只传状态 / 待办 / 一句话，不传坐标）
┌───────▼──────────── DSH 插件 dsh-wechat-usb（瘦适配层）───────────────┐
│  bridge：每 8s 轮询 /pending → schedule.create 叫醒一个会话           │
│  工具：wechat_reply_pending / wechat_read_link / wechat_skip_pending  │
│        / wechat_status / wechat_shot / wechat_config …               │
│  守卫：交接模式下旧执行工具一律拒绝（单写者纪律）                      │
└───────┬─────────────────────────────────────────────────────────────┘
        │
┌───────▼──────── DSH 会话（人格 + 记忆 + 判断）────────────────────────┐
│  决定「要不要接」→ 说什么 → 发文字还是发表情 → 要不要先点开链接读一遍   │
└──────────────────────────────────────────────────────────────────────┘
```

为什么这么切：

- **引擎**要的是确定、可回放：红点怎么认、消息怎么去重、什么时候不该回，全写成代码。
- **会话**要的是像她：语气、这个人的关系、能不能开玩笑，只有 DSH 里有。
- **引擎不编话**（本地 4B 说话太差），**插件不碰 adb**（旧 poller 的教训）。

## 2. 一条入站消息（自动监测 → 自动回复）

```
列表红点 ──► 扫列表(OCR+红点连通块) ──► 选会话(白名单→未读优先)
   ▲                                          │
   │ 回列表 20s 后下一轮                       ▼
   │                                    点会话行 → 等 chat 页
   │                                          │
   │                                     核对标题（不对就退回重扫重试，最多 3 次）
   │                                          │
   │                                    读消息区 OCR → 左右分边 → 合并气泡
   │                                          │
   │                                    世界去重（多重集）→ 新增消息 fresh
   │                                          │
   │                                    策略 decide()（静默/冷却/限频/群聊 judge）
   │                                          │ 要回
   │                                    挂成待办（PendingQueue，5 分钟过期）
   │                                          │
   └──────────── HTTP /pending ◄───────────────┘
                        │
          bridge 8s 轮询 → schedule.create 唤醒会话（prompt 带最近 8 条 + 待办 id）
                        │
          主模型 → wechat_reply_pending({id, text}) 或 {id, stickerMood}
                        │
          POST /pending/reply ──► 引擎：进会话 → 切输入法 → 打字 → 点发送 → 校验
                        │
                  send.succeeded（事件流里可查）
```

要点：

- 一轮 tick 只处理**一个**会话（单窗口是物理约束），多会话在时间上轮流。
- **所有会真的发东西的路径，进会话都要核对标题**（`src/daemon/navigate.ts`）：
  点完读标题栏，对不上就退回列表重扫重点（最多 3 次）；还不对就**走搜索框**把会话名打进去、
  点搜出来的那一条，再核对标题（最多 2 次）。只有「列表 + 搜索」都确认不了才不发 —— 不是一错就放弃。
  这条是 2026-11-17 下午补的：收到「回复发到某个群」的现场报告，根因是发送路径的 enterChat 只等「页面变 chat」、没核对标题。
- 设备只有一把锁（`exclusive`）：tick 撞到忙就跳过；**主模型的发送/读链接会排队等锁**（45s / 30s），不会因为「设备忙」静默失败。
- 群聊没 @ 时不是硬闸：`groupStrategy=judge` 时挂起并标注 `needsJudgment`，由主模型决定接不接（实测它会跳过纯闲聊）。

## 3. 一条链接（对方丢来推文 / 视频）

```
消息区 OCR 认出「标题 + 来源」对 ──► 该条消息标成 [链接] 标题 · 来源
        （视频卡的「播放：1.2万」是元信息，标题取它上面那行）
                    │
   唤醒 prompt 里出现 [链接] ──► 主模型调用 wechat_read_link({chat})
                    │
       POST /observe/link ──► 引擎进会话 → 找卡片（当前屏 → 回底部 → 逐屏往上，到边就停）
                    │
           点卡片 → 等文章页 → act.scroll_to_top（滚到「再滚也不动」为止）
                    │
        ① AI 摘要：点「AI摘要」→ 小微 Flutter 视图 → 等文字稳定 → OCR
        ② 摘要读不到（视频/非公众号）→ 退回正文 OCR（两屏）
                    │
              把文本回给会话（≤6000 字）→ 模型读完再决定怎么说
```

实测：摘要路径 31–53s，正文兜底 50s。链接读回来后模型会结合内容回话（不是复述标题）。

## 4. 表情（发 / 收）

- **发**：模型在 `wechat_reply_pending` 里只给一个情绪（开心/无语/敷衍/惊讶/亲昵/嘲讽/委屈），引擎从收藏面板按情绪挑一张发出去。实测一次 19s。
- **收**：对方发来贴纸时自动收藏（长按 → 收藏），视觉打标（qwen3-vl）判断情绪 / 标签 / 好玩程度，`funny ≥ 0.7` 才入库，每小时最多 2 张。
  ⚠ 本机 Ollama 没起时**不会**去碰手机：启动时探一次 `127.0.0.1:11434`，不可用就只记一条原因。

## 5. 主动搭话（不是重新造调度）

「什么时候开口」交给现成的 **dsh-speak-up** 插件：它按间隔掷骰子（峰/谷命中线、没中加成、安静时段、搭话冷却都在它那边），
掷中之后往目标会话里投一句「好久没人跟我说话了…」。我们只补两件事：

1. **出口**：引擎 `POST /say {chat, text|stickerMood}` —— 安静时段、每小时 2 次、每天 8 次、两次间隔 ≥20 分钟、
   群聊开关（`policy.proactive.allowGroups`）五道闸都在引擎侧，拒绝会带原因回给模型。
2. **挑会话**：插件工具 `wechat_chats`（最近聊过谁）+ `wechat_say`（发出去）。

⚠ 已知边界（插件自己的设计，README 写明）：**它只往「活着的」会话投递，不会唤醒冷会话**。
所以要么把目标会话（syotenyuyu 那个）在 GUI 里开着，要么退回到「有消息才动」。
要「一定自己开口」的话，得让 bridge 定时唤醒一次（那才开始有点像自己写调度）。

## 6. HTTP 契约（127.0.0.1:65480）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 存活、暂停、干跑、当前页面、上一轮结果 |
| GET | `/state` | 世界快照 |
| GET | `/events?afterSeq=&limit=` | 增量事件（监控/回放） |
| GET | `/skills` | 技能清单 + 校验问题 |
| GET | `/pending` | 待回复队列 |
| POST | `/pending/reply` | `{id, text}` 或 `{id, stickerMood}` → 引擎发送（会等锁） |
| POST | `/pending/skip` | `{id, reason}` → 跳过并落事件 |
| POST | `/pending/inject` | **测试用**：不等真消息也能验整条链（需启动加 `--allow-pending-inject`） |
| POST | `/observe/link` | `{chat, which?}` → 读一条链接，返回标题与正文 |
| POST | `/intent` | `{skill, params}` → 直接跑一个技能（走同一把设备锁） |
| POST | `/say` | `{chat, text?/stickerMood?}` → 主动搭话（五道闸） |
| POST | `/control` | `pause`/`resume`/`dry_run`/`wet`/`tick` |

## 7. 今天已真机验证过的（2026-11-17）

| 链路 | 结果 | 证据 |
|---|---|---|
| 引擎挂起 → 唤醒会话 → 模型读链接 → 回话 | ✅ | 待办 14:19:03 注入，14:19:30 起读链接，摘要 52.8s，回「还没点开呢，你这是想家了？」并发出（send_text 7.7s） |
| 表情（交接） | ✅ | `send_sticker_mood` ok 19.0s，`send.succeeded {stickerMood:"开心", via:"handoff"}` |
| 群聊 judge（没 @） | ✅ | 引擎挂起并标 needsJudgment；主模型 `wechat_skip_pending`「群里在聊旧事和视频链接，没 @ 我也不问我，不硬接」 |
| 链接卡片进世界模型 | ✅ | `note link-card {title:"播放：1·2万", source:"哔哩哔哩", marked:true}` |
| 进错会话重试 | ✅（单测） | 标题对不上 → 退回列表重扫重点，最多 3 次，仍不对才放弃 |
| 自动监测循环 | ✅ | 20s 一轮；进错会话、点不开都落 reason，下一轮继续 |
| 自动收藏表情 | ✅ | 起 Ollama（qwen3-vl:4b-instruct），收藏 3 张并打标：无语/0.7/无奈、惊讶/0.8/震惊；单次打标 3.6s |
| 主动搭话出口 | ✅ | 主模型按用户要求用 `wechat_say` 往群里发表情，`send.succeeded {via:"proactive"}` |
| 浮层自救 | ✅ | 收藏中途被重启留下的长按菜单挡住 → 下一轮按返回收掉继续（单测覆盖） |

## 8. 已知限制（诚实清单）

1. **OCR 是主感知**：微信 a11y 全封，只能截图 OCR；群聊昵称小字常被滤掉，个别消息会串行或读错字。
2. **读链接慢**：30–55s，期间设备被独占，新的 tick 会让路。
3. **自动收藏依赖本机视觉模型**（qwen3-vl @ Ollama，现在起着；没起时引擎只记一条原因、不碰手机）。
4. **只支持一台手机、一个微信**；多开/多账号未做。
5. **长文只读前两屏**（人有扫读习惯，全文 OCR 不划算）；要引用原文再单独加。
6. **主动搭话**接的是 dsh-speak-up，但它只投「活着的」会话（见 §5）；冷会话下不会自己开口。
7. 插件改 `lib/*.js` 后要在设置里重载插件（DSH 不支持插件代码热更），引擎可以随便重启。

## 9. 怎么跑

```bash
# 引擎（独占手机）
node tools/daemon.ts --adb "<adb>" --interval 20

# 状态 / 暂停 / 继续
curl -s 127.0.0.1:65480/health
curl -s -X POST 127.0.0.1:65480/control -d '{"action":"pause"}'

# 离线自测（149 个用例，不需要手机）
node --test
```

配置：`data/config.json`（白名单、静默时段、群聊策略、表情收藏开关）。
插件侧：`wechat-usb.config.json` 的 `bridge.enabled / sessionId / engineUrl`。
