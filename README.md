# mimicd · 拟真控制终端

用一台真手机、一根 USB，让 DeepSeek **像人一样**看微信、决定要不要开口、然后用自己的手把它发出去。

这个仓库是引擎。不是 DSH 插件。

## 形态：三个部件，两个进程

```
┌─────────────────────────── DSH ────────────────────────────┐
│  dsh-wechat-usb（瘦适配层，旧仓库）                          │
│    wechat_* 12 个工具 → 转发给引擎；设置页；守卫的最后一层    │
└───────────────┬────────────────────────────────────────────┘
                │ HTTP 127.0.0.1 + token（只读状态 / 提交 Intent）
┌───────────────▼────────────────────────────────────────────┐
│  mimicd（本仓库，独立进程，可单独回放/测试）                  │
│    感知 → 世界模型 → 意图 → 节奏 → 编排 → 拟真 → 执行        │
└───────────────┬────────────────────────────────────────────┘
                │ adb（USB）
┌───────────────▼────────────────────────────────────────────┐
│  真机微信 1080×2160  +  /data/local/tmp/injector.dex        │
│    （android/injector：自建触摸注入器，唯一需要构建的部件）    │
└─────────────────────────────────────────────────────────────┘
```

- **引擎（mimicd）**：唯一能改设备状态的地方。事件流、回放、Humanizer、稳定帧判据都在这里。
- **适配层（旧仓库）**：只做「DSH 工具面 + 设置页 + 人话错误」，不含动作逻辑。M3 之后基本不再改。
- **注入器（android/injector）**：`app_process` 起 dex，可控 deviceId 之外的所有事件参数（压力/面积/时间戳/history/toolType），免 root。它和引擎的版本必须一起动。

## 为什么单独开仓库

见 [`DECISIONS.md`](DECISIONS.md) 的 D5/D6。一句话：引擎不是发布物，插件是；引擎需要离线回放，插件不能拖 DSH 起来；旧仓库是每天在跑的产线版本，不该为重构冒断线风险。

## 现在有什么（M0 地基 + 能力层骨架）

- `src/events.ts`：事件信封 schema v1（双时间戳、schema 版本、只增不删）
- `src/eventlog.ts`：JSONL 追加写 + 严格回读（拒绝未来版本）
- `src/artifacts.ts`：内容寻址的图片仓（路径 + sha256，**事件里不存 base64**）
- `src/skills/`：技能结构 + 校验器 + 注册表；`skills/wechat/` 已有发表情 / 收藏表情 / 读链接三个技能
- `docs/behavior-layer.md`：**「用法像人」怎么做**（多路感知 / 页面图 / 能力 / 注意力 / 记忆）
- `docs/research/`：设计前调研原稿（四份分册的合成稿 + 目标分层图）

```bash
node --test             # 15 个离线用例：事件流、工件仓、技能契约，不需要手机
```

## M2：自动监测 + 自动聊天（2026-11-17）

`node tools/daemon.ts --adb "<adb>" --interval 20` 起一个 daemon：
扫列表红点 → 进会话 → OCR 读尾部 → 去重 → 策略判定 → 脑子出稿 → 技能发送 → 回到列表，全程落事件，
同时提供 `127.0.0.1:65480` 的 HTTP（/health /state /events /intent /control /skills）。
架构与验证矩阵见 [`docs/architecture-m2.md`](docs/architecture-m2.md)。

## M1 进度（2026-11-17 夜）

已落地并在真机跑通：

- **device 层**：adb（异步）、注入器（TCP）、输入法（广播）三个端口，全部可替身测试
- **actuator**：单写者队列、动作即事件、dryRun
- **humanizer**：种子随机、按压 40–180ms、落点框内高斯、滑动缓出
- **perception**：页面判定（活动名 + 像素兜底）、区域稳定帧、深色浮层定位、Windows OCR
- **skills runner**：pre/steps/post、预算、未实现操作直接报错；已跑通 `wechat.send_text`（真发中文）与 `wechat.read_screen`（OCR）
- **零 OCR 读消息**：长按气泡 → 定位浮层 → 点复制 → 读剪贴板，逐字一致

## 路线

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M0 | 事件流 + 回放地基 + 技能契约（本仓库现状） | 事件可回读、版本可拒、工件不内联、技能无坐标 |
| M1 | 感知多路（a11y / 通知 / 剪贴板往返 / dumpsys）+ 页面图 v1 + 稳定帧 + 功能地板 | 文本抽取零 OCR 误差；未知页面 100% 记事件并退回 |
| M2 | 三个技能真机跑通 + 贴纸库（哈希 + 标签）+ 记忆写入 | 每个技能连续 20 次成功 ≥18，失败全部可解释 |
| M3 | 注意力调度（三驱动 + 预算 + 让位）+ 探索技能 | 连续 6 小时无人干预，主动行为不重复、不越预算 |
| M4 | shadow 双跑 → 切换；旧插件退化为薄壳 | 新旧决策逐条对照零差异；L3 任务指标不降 |

原计划的「Humanizer 统计拟真」已降级为功能地板（DECISIONS D11）：按压 ≥40 ms、文本逐字、滑动留末速。不做运动学拟合。

## 纪律（写进代码，不只写进文档）

1. **坐标不出模型**。模型只出 Intent；落点由页面图 + Humanizer 从目标矩形里采样。
2. **技能闭集**。只能从注册表里挑技能 + 传参数；技能 JSON 里出现像素坐标会被校验器直接拒掉。
3. **不用 sleep 表达等待**。等稳定帧、等元素出现；只保留「最小间隔下限」。
4. **事件里不存 base64**，只存路径 + 哈希 + 尺寸；带 schema 版本，只增不删。
5. **单写者**。引擎是唯一执行者；适配层不许兜底自己发。
6. **读不到就不动**。低置信度不是「猜一下」，是不开口；未知页面记事件后退回。
7. **拟真参数全部可配、可一键关**。调试时要能回到「傻快」。
